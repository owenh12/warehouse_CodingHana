## 1. 구현 내용

| 모듈 | 내용 |
|---|---|
| `data/vision.py` | data.binance.vision 아카이브: S3 목록(상장폐지 포함), 월 zip → 없으면 일 zip(어제까지), SHA-256 검증, 5xx·429 재시도(지수 대기), 404·영구 오류는 재시도 안 함, 헤더·ms/µs 자동 판별 |
| `data/cache.py` | 월 파티션 Parquet(zstd) + manifest. 월말+3일 뒤 받은 파티션은 확정(다시 안 받음). 진행 중인 달은 지난 수집일 2일 전부터 이어 받기. 스레드 풀 병렬 |
| `data/resample.py` | 5분봉 → 15m/1h/4h/1d (epoch 경계 = 바이낸스, 1d = 00:00 UTC). 미완성 버킷 제외, 버킷별 원천 봉 수 기록. 실시간용 증분 `BarAggregator`(일괄과 동일, 시각 역행·중복 거부) |
| `data/quality.py` | 결측 구간, OHLC 모순, 거래 없음 봉(체결 0·고정가), 거래 중단(12봉↑ 연속), 상장폐지 시각(끝까지 이어지는 거래 중단의 시작) |
| `data/store.py` | `MarketData`: 원천 5분봉 → 거래 중단 봉 제거 → 리샘플, 품질 보고 동봉. 펀딩비 |
| `data/symbols.py` | 계약 이름 해석(`1000PEPEUSDC`, `ETHUSD1`, `...SETTLED`, 분기물 제외), 코인 단위 묶기, 주문 계약(USDT) 선택 |
| `data/universe.py` | 코인 거래대금(USDT+USDC+USD1 합산), 롤링 24h(행 T = `[T−24h, T)` 마감 봉), 순위, 순위 구간, TradFi 판별 지표(주말 비율·시간대 비중) |
| `data/rest.py` | ccxt `binanceusdm` 원본 엔드포인트(klines 거래대금·체결 수 포함, 진행 중 봉 제외, 페이지 처리), 펀딩비, exchangeInfo(underlyingType·필터). 451 은 즉시 실패 |
| `data/validate.py` | 리샘플 결과 vs 아카이브 원본 15m/1h/4h/1d 대조 |
| `data/check.py` | 데이터 확보 점검 (§3.1) |
| `indicators/wilder.py` | Wilder RMA(SMA 시드) 공용 루프 — 일괄·증분이 같은 산술 순서 → 비트 단위 동일 |
| `indicators/rsi.py`·`atr.py` | RSI(종가, 14, Wilder), ATR(14, Wilder). 일괄 + 증분(`RsiState`, `AtrState`) |
| `indicators/pivots.py` | L/R 피벗, 동률 규칙 `strict`/`first`, 확정 시점 `i+R`, 증분 `PivotTracker` |
| CLI | `config`, `secrets`, `data-check`, `resample-check` |

## 4. 리스크·가정 (승인 필요 항목은 ★)

1. ★ **TradFi 제외 목록 (181개)** — 이 환경에서 exchangeInfo(fapi)를 받을 수 없어 판별식으로 만들고 검토했다.
   - 판별식: 주말/평일 일간 변동 비율 < 0.45 **또는** 평일 변동의 미국장(13~21 UTC)·아시아장(0~8 UTC) 8시간 비중 ≥ 0.45.
     주말 비율만 쓰면 NVDA·MU·GOOGL 등은 잡히지만 NATGAS·BRKB·PYPL·HD·XBI·EWZ·MRK·POPMART·HANMI 등이 빠졌다 → 시간대 기준 추가.
   - 검토 결과 암호화폐로 남긴 것: **ANT**(Aragon, 현물 상장), **IR**(시간대 비중 균등 0.37/0.31, 2025-12-21 상장) — IR 은 후보군(순위 16위 안)에 든다.
   - 판별식이 못 잡아 수동 추가: **ANTHROPIC**(비상장 주식), **EWZ**(ETF), **BNC**(주식, TradFi 상장 묶음과 같은 날).
   - 비상장 주식 연동(OPENAI·ANTHROPIC·SPCX·MINIMAX·ZHIPU·UNITREE)과 금 연동 토큰(PAXG·XAUT)도 TradFi 로 뺐다.
   - 판단 보류(제외 안 함, 후보군 밖이라 결과 영향 없음): DOS, DATAIP.
   - **주의**: BTC 자체가 주말 비율 0.48·미국장 비중 0.43 으로 기준에 가깝다. 그래서 실행 중에는 판별식을 쓰지 않고 설정 목록만 쓴다.
     실거래 전 국내 PC 에서 exchangeInfo `underlyingType`/`underlyingSubType` 로 목록을 대조한다(7단계 체크리스트).
   - TradFi 상장은 모두 2025-12 이후라 2024~2025 구간에는 영향이 없다. 2026 구간에서는 NVDA·MU·GOOGL·SNDK·CL 등이
     1시간 순위 16위 안에 든 적이 있어, 제외 여부가 유니버스를 바꾼다.
2. ★ **후보군 방식** — 1시간 순위로 후보를 추리고(여유 6), 신호 시각 순위는 후보 안에서 5분봉으로 정확히 계산한다.
   표본 4개월에서 5분봉 상위 10 이 모두 후보군 안에 있었다(후보군 밖 0개). 표본 밖의 극단적인 날(신규 상장 폭증 등)에
   후보 밖 코인이 상위 10 에 드는 경우가 이론적으로 가능하다 → 4단계에서 후보 경계(순위 16위 근처) 코인의 빈도를 다시 보고한다.
3. **용량·시간** — 후보 코인 5분봉 3.14 GB(순위 구간만), 1분봉 14.0 GB. 이 환경의 측정 속도(1.7 MB/s)로 5분봉 약 30분,
   1분봉 약 2.3시간. 5분봉은 4단계 시작 때 받는다.
   ★ 1분봉 정밀 모드는 전체 수집 대신 "같은 15분봉에서 손절·익절이 모두 닿은 날"의 1분봉 일 파일만 받는 방식을 제안한다
   (해당 거래당 하루치 수 MB).
4. **펀딩비** — 후보 전부 월 파일이 있다. 아카이브에 일 단위 펀딩 파일이 없어 **이번 달(진행 중)** 펀딩비는 비어 있다.
   ★ 백테스트 끝을 "현재"로 둘 경우 마지막 부분 달은 펀딩 0 으로 두고 표시(국내 PC 에서는 REST 로 채움) — 이대로 진행할지 확인 필요.
5. **REST(ccxt) 경로 미검증** — fapi 가 이 환경에서 451 이라 가짜 거래소로만 테스트했다. 국내 PC 에서
   `python -m perpdiv source-check` 로 아카이브 = 거래소 봉을 확인한다(6·7단계 전 필수).
6. **상장폐지** — 후보 중 98개가 기간 중 폐지(데이터 끝까지 체결 0 고정가). 거래 중단 봉은 리샘플 전에 빼고,
   보유 중 폐지되면 마지막 체결가로 청산 기록(4단계). `...SETTLED` 시리즈는 정산일 하루치뿐이라 합산 영향 없음.
   티커 변경(EOS→A, FTM→S, MATIC→POL 등)은 별도 계약이라 다른 코인으로 취급하고, 새 계약의 지표는 상장 첫 봉부터 다시 쌓인다.
7. **BUSD 계약(41개)** 은 모두 2023-12 에 끝나 2024~ 순위에 영향 없음. USDC 40개·USD1 3개는 1 USD 로 환산해 합산(가정).
8. ★ **피벗 동률 `strict`** — 15분봉에서 SOL·DOGE 는 피벗의 약 3% 가 동률로 빠진다(§3.4). 요구사항 문구대로 유지할지 확인 필요.
9. **RSI 정의 차이** — 완전 횡보(상승·하락 평균 0)는 50 으로 정의(TradingView 는 NaN→직전 값). 상위 코인에서는 사실상 발생하지 않는다.
10. **이 달 데이터** — 진행 중인 달은 어제까지의 일 파일. 캐시는 지난 수집일 2일 전부터만 이어 받는다.
11. 1단계에서 넘어온 확인 사항 (3단계 신호 구현 전 결정 필요):
    - ★ p2 유효성: 피벗이 아닌 봉(동률 등)이 p2 보다 높으면 그 (t1, p2) 는 신호를 낼 수 없다고 해석. [t1, t3−1] 에 t1 봉의 High 도 포함.
    - ★ 사이징 fee_buffer 0.2%, 트레일링 스탑 정의(DESIGN §6), BTC Buy & Hold = BTCUSDT 무기한 1배 롱(수수료·펀딩 반영).
